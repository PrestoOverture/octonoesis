# Outcome utility and insight retrieval

Xiong et al., ACL 2026, [How Memory Management Impacts LLM Agents](https://aclanthology.org/2026.acl-long.27/), motivates history-based removal using subsequent task evaluations. This implementation uses the existing verified-recovery proxy: only a fresh verification of the exact injected command is eligible; PASS with exit 0 is a hit, other eligible verdicts are misses. This measures recovery after advice, not causal correctness of advice.

Utility policy (chosen a priori, independently of held-out runs): a symmetric Beta(2,2) prior, break-even probability 0.5 (equal cost of unhelpful and helpful exposure), and eight distinct sessions before decisions. Each rule receives at most one utility observation per session, identified by a SHA-256 session digest. Eight sessions require repeated independent exposure rather than one noisy session. Promote when the central 95% credible interval is wholly above 0.5; retire when wholly below 0.5; otherwise demote active to candidate when the posterior mean is below 0.5. The minimum count and conservative interval intentionally defer uncertain decisions. Utility excludes distilled repair-evidence pseudocounts and legacy counters without session provenance. Existing confidence counters remain available. Rules with utility observations cannot be promoted by the older repair-evidence shortcut. Pinned/banned and terminal statuses remain protected.

`OCTONOESIS_DISABLE_RULE_UTILITY=1` disables utility learning and decisions (also accepts true/yes/on). Outcomes are journaled as `rule_utility` with configuration, counts, before/after statuses and retirement reason. Retired rules are written to `rules/archive` before removing the hot copy; rebuild preserves utility evidence and retirement status/reason. Missing anchors and pool overflow also record reasons. Persistence failures remain best effort and cannot change task exit codes.
