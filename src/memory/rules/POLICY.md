# Outcome utility and insight retrieval

Xiong et al., ACL 2026, [How Memory Management Impacts LLM Agents](https://aclanthology.org/2026.acl-long.27/), motivates history-based removal using subsequent task evaluations. This implementation uses the existing verified-recovery proxy: only a fresh verification of the exact injected command is eligible; PASS with exit 0 is a hit, other eligible verdicts are misses. This measures recovery after advice, not causal correctness of advice.

Utility policy (chosen a priori, independently of held-out runs): a symmetric Beta(2,2) prior, break-even probability 0.5 (equal cost of unhelpful and helpful exposure), and eight distinct sessions before decisions. Each rule receives at most one utility observation per session, identified by a SHA-256 session digest. Eight sessions require repeated independent exposure rather than one noisy session. Promote when the central 95% credible interval is wholly above 0.5; retire when wholly below 0.5; otherwise demote active to candidate when the posterior mean is below 0.5. The minimum count and conservative interval intentionally defer uncertain decisions. Utility excludes distilled repair-evidence pseudocounts and legacy counters without session provenance. Existing confidence counters remain available. Rules with utility observations cannot be promoted by the older repair-evidence shortcut. Pinned/banned and terminal statuses remain protected.

`OCTONOESIS_DISABLE_RULE_UTILITY=1` disables utility learning and decisions (also accepts true/yes/on). Outcomes are journaled as `rule_utility` with configuration, counts, before/after statuses and retirement reason. Retired rules are written to `rules/archive` before removing the hot copy; rebuild preserves utility evidence and retirement status/reason. Missing anchors and pool overflow also record reasons. Persistence failures remain best effort and cannot change task exit codes.

Kim et al., 2026, [Memory Transfer Learning](https://arxiv.org/html/2604.14004v1), sections 4.3.3 and 4.4.5, supports abstract task-agnostic insights and similarity retrieval without LLM reranking. The paper uses embeddings; lexical TF-IDF is our deterministic keyless adaptation, not a replicated finding about lexical retrieval.

The distiller additionally requests a task-agnostic 1–2 sentence insight (400 characters maximum); it stores that separately from failure advice and the originating scrubbed task excerpt (6,000 characters maximum). Legacy rules or responses lacking an insight remain valid for exact matching, but cannot participate in insight retrieval. No traces or task excerpts are injected.

Session start ranks repo-scoped candidate/active/pinned insights by TF-IDF cosine similarity of the new scrubbed task and stored scrubbed task excerpts. Tokenization uses lowercase Unicode letters/numbers/underscore, drops one-character terms and a fixed stop list (including scrubber placeholders). TF is `1 + ln(count)`; IDF is `1 + ln((1 + N)/(1 + document_frequency))` across eligible excerpt documents. Empty vectors score zero. Sort by descending score, then bytewise rule ID. The fixed minimum cosine is **0.2**, an a priori angular-overlap floor (about 78.5 degrees), chosen to reject near-orthogonal tasks; at most **two** insights are included to bound exposure. These are engineering defaults, not thresholds fitted to held-out results. Retrieval uses no provider, embeddings, reranking or live evaluation.

`OCTONOESIS_DISABLE_INSIGHT_RETRIEVAL=1` independently disables this channel (true/yes/on also accepted); the existing memory-off switch disables both mechanisms. First-query `insight_retrieval` journal events record both feature settings, algorithm version, minimum score and the ranked IDs/scores actually retained by prompt compilation, including empty exposure. Insight blocks are optional heuristics that never override the task contract. They persist in the session context on subsequent queries without a second session-start exposure event. Failure-triggered signature matching is unchanged.
