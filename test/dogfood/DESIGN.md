## Decision after rounds 4 and 5: observe the learning path

Round 5 (`b74a32e`, six fresh-ledger sessions per family, concurrency 10) had hidden final-submission failures 0/6 overlay, 0/6 transfer, 2/6 cache (including one max-turn exit), 0/6 event-bus and 2/6 pool: 4/30 overall. No fatal errors recurred; train-17 exhausted its turn budget. Lower load is a plausible explanation for the operational improvement, not a controlled causal result. Evaluation **and calibration concurrency are capped at 10 in code**, and the chosen worker count is immutable in the preregistration. A valid `max_turns` result is task FAIL; wall-clock budget exhaustion is also task FAIL, including deadline termination before JSON/journal flush. External kills, spawn/fatal/provider failure, missing JSON/journal outside deadline exhaustion and verifier infrastructure failures remain ERROR.

The old endpoint was poorly aligned: a final hidden omission cannot teach the loop because the oracle runs after session end. We choose redesign (b), not an assumption of a nonzero hidden-score effect. The fixed round-5 semantic contracts and hidden checks are retained. Difficulty is set once by exposing a small recurring semantic regression in each family's public test (tag boundaries/peeling, retry deduplication, stale rejection ownership, snapshot dispatch, pre-start cancellation). These are examples of the stated contracts, not oracle feedback. Training now observes the relevant failing repair and its correction. The same family classes recur in held-out variants; independent hidden cases vary the inputs/interactions and remain inaccessible during every session. This shifts measurement from eventual completion to whether learned advice prevents an early wrong tested repair. No stronger agent restrictions, turn limits or production changes are introduced.

The **primary endpoint is first tested repair success**, conditional on the final hidden regression guard. On every invocation of the generated `contract.test.ts`, before dynamically importing the implementation, it appends the current `src/subject.ts` bytes and timestamp to an external per-session `attempts.jsonl`. Thus Bash edits, syntax errors and shell pipelines cannot erase a tested state merely by returning a zero shell code. The first recorded source differing from the supplied baseline is the first tested repair; multiple edits before testing form one attempted state. Unchanged baseline tests are excluded. After session exit the harness reconstructs that state in a separate directory, runs the retained original public assertions and independent hidden oracle with credential-free environments, and retains `first-public.json`/`first-check.json`. PASS requires both first-state checks, a completed session, and the final hidden check to pass. An absent tested repair, max-turn exhaustion or agent wall-clock budget exhaustion is FAIL. Deadline exhaustion is committed immediately as FAIL even without headless JSON, snapshots or a journal; no grader result can turn it into a success. Corrupt measurement records, changed canonical public tests or grader infrastructure failures are ERROR. The final hidden score and final public score remain descriptive guards, not the primary endpoint.

Only the canonical contract-test invocations are measured: ad-hoc tests before that first invocation are not counted. The prompt asks for direct `bun test` without pipelines so failures reach the unmodified production verifier. The primary result is independently replayed, not copied from a potentially masked shell exit or model self-report. Snapshot logging alone does not prove learning: confirmation additionally requires at least three families with an actual non-stale production FAIL verification after a tested repair, a subsequent non-stale production PASS verification, and a hidden-correct final submission. No hidden outcome is appended to the production journal. Later repairs remain allowed; turns/tokens quantify the rest of the session. Rules-on may help after baseline failure or at session start, according to existing production eligibility; this estimates access to trained rules, not unconditional first-edit accuracy.

## Hypothesis and estimand

Rules accumulated by the unmodified loop during sequential training improve **first tested repair success** on held-out variants, compared with withholding the same trained rules. The estimand is the paired difference in the first tested changed-source state passing original public and unseen independent checks, with a final hidden regression guard. The detailed recording/attempt definition is above. The agent may inspect, edit, write separate regression tests and iterate normally. Training sees public semantic failures and repairs, never hidden outcomes.

This is an RSC measurement baseline: a causal ablation of learned rules, not a claim that R1 parameter regression or R2 distiller search has been implemented or won. A positive result would justify further rung comparisons; it would not by itself justify a production parameter change.

## Task stream and hidden checks

`tasks.ts` generates and validates `stream.json`; `task.json` is retained per session outside the agent repository. For stream seed 1, training starts at seed 1000 and held-out starts at seed 100000, in disjoint reserved namespaces. Each additional `--stream-seed` shifts both by one million. Families recur in round-robin order: eight training variants each and equally many held-out pairs per family, computed by power planning or fixed with `--pairs-per-family`. Public example values, tags, cache keys and clocks vary with the seed; hidden oracle workloads also vary with it. All variants of a family intentionally share the same API and source/test paths, enabling cross-session rule reuse.

| Family | Required behavior | Hidden discrimination |
|---|---|---|
| Interval overlay | Ordered paint history, half-open intervals, null-tag peeling, coalescing, no mutation or point enumeration | Repeated equal-tag history survives coalescing; peel reveals older paint; seeded point-stack oracle including empty strings and uncovered peels |
| Atomic transfer | Simultaneous exact batch, retry-ID deduplication/conflict detection, immutable input, own account keys | Empty/prototype IDs, conflicting self-transfer IDs, anonymous repeats, wide intermediate totals that lose precision under floating-point arithmetic, invalid values and own keys |
| Single flight cache | Pending request deduplication, completion-based TTL, rejection recovery, generation ownership on invalidation | Deterministically controlled promises settling out of order, stale rejection, undefined values, independent keys, expiry boundary, synchronous throw |
| Event bus | Synchronous snapshot dispatch, independent duplicate registrations, once-before-call, reentrancy and ordered AggregateError values | Listener addition/removal during dispatch, nested consumption of once listeners, prototype event names, falsy thrown values and nested AggregateError preservation |
| Async pool | Microtask FIFO scheduling, fixed capacity, pre-start cancellation, exactly-once release | Reentrant tail scheduling, queued/pre-start abort, ignored running abort, sync throw recovery and cancellation skipping |

Five additional domains use the same spec-only fixture boundary and seeded public/hidden separation:

| Family | Public recurring trap | Hidden discrimination |
|---|---|---|
| CSV records | Quoted delimiters and doubled quotes | Seeded encoder round trips, CRLF, empty records, malformed quotation |
| Dependency plan | Duplicate edges and lexical ready-node selection | Seeded DAG oracle, disconnected/prototype nodes, cycles and unknown endpoints |
| Merge patch | Recursive deletion versus shallow assignment | Frozen nested inputs, array replacement, independent deep copies, prototype data keys |
| Civil date | Rejecting normalized impossible dates | Independent month-length stepping, leap centuries, years 0001–9999, invalid offsets |
| Ranked vote | Recount after deterministic tied elimination | Seeded independent rounds, exhausted ballots, unknown/repeated rankings, empty names |

`extra-tasks.ts` holds their complete visible clauses; `extra-check.ts` holds independent private groups. Every clause must be cited by a group; deleting any clause from any family's prompt fails the coverage audit. All registered families have repeat-materialization and seeded-oracle replay tests, including stream seed 4. Calibration automatically enumerates all registered families. No new live difficulty results are asserted.

Hidden assertion groups in `check.ts` cite verbatim clauses from `tasks.ts`; those clauses are rendered into both the prompt and README. Coverage tests reject a missing clause, specifically the old TTL text that did not require RangeError. The audit also removed the unstated assumption that loaders start after exactly one microtask. The checker polls for loader startup within a per-group deadline instead. Each group has a 4-second promise-race deadline (at most five groups, inside the 30-second process budget); a never-settling submitted implementation fails that group with its clause IDs, and later independent groups still run. Oracle polling is aborted at the deadline; the checker exits explicitly after emitting results so submitted-code handles cannot keep it alive. A synchronous loop can block the race, so an outer checker timeout also grades the submitted code FAIL, in both first-state replay and final checks. Unexpected oracle exceptions, missing grader inputs and checker launch failures remain ERROR (the checker uses exit code 2 for infrastructure exceptions). Assertion failures and exceptions originating in the submitted source remain FAIL. The cache retry assertion also treats a retained rejection from the deliberately throwing oracle loader as a contract failure, regardless of the Error’s creation stack. The 900-second agent-session deadline is unchanged; exhausting that agent budget is task FAIL, like max-turn exhaustion. Spawn/provider failures and external kills remain ERROR. Each group emits a private `group_start` and `group_result` JSON line carrying its ID, clause IDs, pass/fail and a bounded assertion message. Ordinary group failures do not stop later independent groups. These lines stay in `check.json` outside the agent context; `Observation.hidden_groups` and the calibration report aggregate failed IDs, clause coverage, counts and session IDs. Clause IDs identify the requirements covered by a failing group, not proof that every covered clause is independently broken. If the checker cannot finish, the report flags incomplete diagnostics; the last private `group_start` identifies the interrupted group. No missing result is fabricated as a pass. Atomic-transfer clauses explicitly define prototype-named own data properties, invalid initial balances, exact simultaneous accumulation with only final-balance validation, and frozen-input support.

The public test starts failing and exposes an ordinary failure → repair → verification arc for the learning loop. Named family-specific exceptions and stable test paths make recurring production fingerprints possible without pre-seeding rules. The harness reads the **actual production journal** and requires a coarse fingerprint to recur in at least two training sessions per family; it does not substitute its own family label for a measured fingerprint.

`check.ts` executes only after the agent process has exited. Only buggy source, a public example test, and the specification README are materialized into its disposable git repository. Oracle source, reference implementations, expected outputs and oracle command paths are never placed in that repository, prompt, tool results or agent environment. The checker has no provider credentials and cannot feed results back into the agent. Agent modifications to public tests do not change external grading. Tests demonstrate that plausible partial fixes fail both the visible semantic regressions and independent hidden cases, while reference implementations pass both. Public assertion coverage remains linked to explicit specification clauses; hidden data/results remain external.

The fixed pooled calibration policy above replaces the old per-family 10–90% gate and the old target of 20–70% in every tiny probe. Family fingerprints and rule eligibility are still measured from actual production artifacts. Any stream/method change requires a fresh output directory; pilots are never pooled into confirmation.

## Design and ledger isolation

1. Create `stream.json` and immutable `preregistration.json` before scheduling any session. The plan records the hypothesis, metrics, exact task/arm order, fixed sample, test, validity gates and stopping rule. It hashes the task stream and executable harness/production sources plus dependency manifests. Each durable `started` event includes the plan hash. Resume rejects changed source, provider, model, stream or an altered plan after scheduling.
2. Train sequentially with memory and automatic distillation enabled. Every session receives a dedicated external `OCTONOESIS_MEMORY_DIR`. Training checkpoint N contains the complete ledger from checkpoint N−1, including journal, episodes, rules and auto-memory. This is one persistent **logical ledger lineage**, implemented as full copy-on-session checkpoints for crash recovery. Successful ledger writes accumulate exactly as in normal use; no rules are manufactured, promoted or rewritten by the harness.
3. Freeze the final trained checkpoint for the comparison. For every held-out variant, make two independent copies of that checkpoint and identical initial repositories. The rules-on arm retains all rule files; rules-off withholds the copied `rules/` directory, including archived rules. All other memory is initially identical. Both run the normal learning loop, including session-end learning. New evaluation learning stays in that session's branch and cannot leak into the other arm or later pairs. This isolates access to previously learned rules while retaining the normal query/verification machinery.
4. Both arms occur exactly once for each task. Independent held-out pairs may execute concurrently from the frozen checkpoint, bounded by the preregistered worker count. A worker starts its second arm only after committing its first arm result. Completion events are serialized and keyed by job ID; reports sort observations into plan order, so concurrent completion order cannot change pair matching or results. No evaluation job starts until all training jobs finish. Their within-pair execution order is chosen by a preregistered hash of the task ID, reducing order drift. The IDs/seeds determine fixtures and ordering; they do **not** seed provider sampling. No override is added to production experiments or query code: train/frozen-held-out paired ablation is used instead of random `src/experiments` assignment, which would not guarantee matched pairs.
5. Preserve per-session `task.json`, `cli.json`, `check.json`, repository and ledger alongside append-only `events.jsonl`. Headless JSON parsing, timeout/process-group termination and status classification reuse `test/eval/run.ts`. A run lock prevents simultaneous writers. Inherited memory-disable and experiment switches are removed in the child environment; parent environment is not changed. Spark's main/distillation model is pinned with MODEL and SPARK_MODEL; the other providers retain their production cheapest-model defaults for distillation, covered by the source hash.

Reports are written only after scheduling finishes and are immutable. Ordinary resume verifies existing reports rather than replacing them. Complete corrupted event lines fail closed. Torn trailing JSON is retained byte-for-byte and followed by a hash-identified recovery marker. A started session without a committed result becomes an operational error, is never retried, and cannot supply its half-mutated checkpoint to subsequent training. Already committed sessions are skipped. Interrupted submissions count as errors under the fixed tolerance below, and cannot be selectively retried. In-flight workers are drained before releasing the run lock on a scheduler failure. Large ledgers are copied in full; storage use grows with checkpoint size.

## Metrics

- **Primary:** paired first-tested-repair success with independent public/hidden replay and a final hidden regression guard. The report gives successes per arm, on-only/off-only wins and risk difference in percentage points.
- **Repeat failure rate:** fraction of evaluation sessions with an observed production coarse fingerprint that occurred in training. A signature is counted once per session. This is an exposure-normalized, coarse session metric rather than the dashboard's weekly resolved-episode occurrence metric. It includes initial baseline verification, so high rates can reflect deliberate reproduction of the supplied bug; do not interpret it as an independent success endpoint.
- **Turns/tokens:** mean headless turns and total input plus output tokens per arm for sessions with valid JSON. These exclude auxiliary provider/fork calls not included in headless usage. Missing usage is not imputed as zero.
- **Rule hit rate:** changes in production rule hit/miss counters, summed over evaluation branches, divided by hits + misses. Undefined when there are no accounted outcomes. This is FR-INJ-1 signature-flip accounting, not a causal success attribution and not a count of session-start impressions.
- **Validity/coverage:** training failure rate and recurring fingerprints by family, eligible rules before each session, operational errors, planned/completed job counts, and reasons an inference is inconclusive.

Agent wall-clock budget exhaustion and max-turn exhaustion are task failures, even if final source happens to pass. A deadline-killed session need not flush headless JSON or a journal to count as FAIL. Spawn failures, invalid JSON outside budget exhaustion, externally killed sessions, fatal/provider exits, missing journals outside budget exhaustion and checker infrastructure crashes remain operational errors. This policy is recorded in every new preregistration; historical runs retain their original classifications. Missing tested repairs are task failures and reduce the explicitly gated snapshot coverage. Completed sessions failing a first-state or final hidden assertion are task failures. Errors remain in the output and count as unsuccessful submissions in the **primary analysis**, not only descriptive rates. Only complete arm pairs enter the paired estimate; missing pairs prevent confirmation rather than silently shrinking the sample.

The fixed operational tolerance allows at most **5% of planned evaluation pairs** to contain one or more errors (floor(planned pairs × .05)), with the **two arm error counts differing by at most one**. It also allows at most **5% training errors** (floor(8G × .05) at the live default). Exceeding any bound forces `inconclusive`. The boundaries and just-over-boundary cases are regression-tested. The calibration failure rate uses valid training submissions; training errors and denominators remain explicit in the report.

A preregistered sensitivity analysis drops **entire pairs containing an error** and repeats the same paired estimate, CI and exact test. Both analyses are printed in JSON and Markdown. Confirmation requires primary and sensitivity p < .05 in the same direction, in addition to the operational and calibration gates; a disagreement is inconclusive. Balanced counts alone do not establish missing-at-random errors, so the report exposes raw counts and both analyses rather than assuming errors are harmless.

## Sample size, power, test and stopping rule

The primary estimand is the **equally weighted mean of family-level paired success differences**. With G balanced families it equals the pooled risk difference, while treating variants within a family as correlated. For each family c compute d_c = mean(PASS_on − PASS_off), then d = mean(d_c) and SE = sqrt(sum((d_c − d)^2) / (G(G−1))). The prespecified two-sided paired cluster t-test uses t = d/SE and G−1 degrees of freedom, with CI d ± t_(.975,G−1) SE clipped to [−1,1]. Reject at p < .05, subject to all calibration/completeness/error/sensitivity gates. Zero or unidentified between-family variance yields p=1 and CI [−1,1], conservatively inconclusive. Entire ERROR-containing pairs are removed in the sensitivity analysis, which keeps equal family weights even when surviving family sizes differ.

This is exact under independent identically distributed Gaussian family means, and a small-cluster approximation for bounded heterogeneous effects. It assumes the selected semantic families represent the intended family population and are independent conditional on the trained ledger. Deliberately constructed domains cannot prove universal coding generalization. Reported per-family paired counts and effects expose heterogeneity; their McNemar p-values are descriptive, without family-level claims or multiplicity-adjusted inference. Tests compare cluster versus naive intervals under perfect within-family correlation and simulate the null with independent symmetric family effects (2,000 seeded repetitions). The default paired t-test is conservative in that discrete, strongly clustered null; this simulation does not establish validity under arbitrary asymmetry or family dependence.

This design follows [Miller (2024), Adding Error Bars to Evals, sections 2.2, 4.2 and 5](https://arxiv.org/html/2411.00640v1): compare paired differences, account for related questions, and preregister power. The Student-t small-cluster correction and explicit equal-family estimand are choices of this harness. The **secondary** analysis retains two-sided exact McNemar on complete pairs with the existing conservative Bonferroni-Wilson paired CI, ignoring family dependence. It never determines the verdict.

Power is computed before stream creation, without reading prior held-out outcomes. Defaults are **MDE +0.05 (5 percentage points), two-sided alpha .05, target power .80, total paired discordance .50, design effect 2, G equal-sized families from `families.length`**. The working variance of a paired difference is conservatively discordance (rather than discordance − MDE²). Family means have variance DE × discordance / m, so the noncentrality is MDE × sqrt(Gm / (DE × discordance)). `power.ts` numerically integrates noncentral Student-t rejection probability over its chi-square denominator with G−1 df, then finds the smallest integer m meeting target power. The minimum allocation m is recomputed for G; totals are Gm pairs and 8G training + 2Gm evaluation sessions. For historical G=10, m=397 (modeled power 0.80019; 396 gives 0.79921). No outcomes from prior held-out runs set these defaults.

`preregistration.json` retains `power_design`: MDE, alpha, target power, assumed discordance/design effect, family count, primary model assumptions, computed pairs per family/total/power, scheduled pairs per family/total/power, and whether the scheduled allocation meets the planning target. `--pairs-per-family N` can override the allocation before starting; `--mde .05 --discordance .5 --design-effect 2` explicitly pins assumptions. Changing any of these on resume is rejected. Dry run schedules four pairs per family regardless of the computed target and makes no efficacy/power claim.

The design effect is an assumption **at the computed cluster size**, not an assertion that cluster correlation disappears with more variants. Under an exchangeable model, DE = 1 + (m−1)ICC; the historical G=10 allocation m=397 implies ICC about .00253. Higher actual ICC or persistent between-family heterogeneity can make +5pp unachievable with a fixed G regardless of variant count. More independent families/training histories may be needed. The Gaussian, equal-family-variance planning model is an approximation, and error/calibration/sensitivity gates can reduce power; a planned run is not a promise of 80% real-world power.

## Threats to validity and scope of conclusions

- Families share contracts and buggy implementation templates. Seeds vary examples/check data, not the underlying algorithm. This tests reuse within known failure classes; it does not establish broad repository generalization. Families are the primary sampling clusters, conditional on one training history. Within-family dependence is allowed. Power assumes independent, approximately Gaussian representative family means and a prespecified design effect; provider drift, caching or shared semantic dependencies across families can still reduce effective sample size. Replication with new preregistered training histories is needed before generalizing.
- Spark may solve all tasks in one session or never produce useful eligible rules. Session-start injection only accepts broad active rules in production; narrow/candidate rules may help only after failure. The harness does not alter lifecycle thresholds or rule specificity to manufacture a lift.
- Public and hidden inputs remain independent. Public semantic regressions now expose the kinds of failures graded by the oracle; unseen combinations may still resist transfer. Fingerprint extraction is provider-dependent, and coarse repeats may group different defects. Gates and raw artifacts expose these failures rather than asserting learning occurred.
- Frozen held-out evaluation measures the effect of the trained rule set. It does not estimate unrestricted continual learning, distiller superiority, or autonomous parameter optimization. Identical auto-memory in both arms may reduce the measured marginal benefit of rules.
- Bypass is appropriate for trusted disposable fixtures, as in the eval runner. Hidden checks are separated by process, path and timing; this is not a security sandbox against a deliberately malicious agent scanning the host filesystem. Run on the architect's dedicated pilot machine/account. Reference implementations are available to the scripted provider only and are never an oracle input to live sessions.
- Hashed within-pair order reduces but cannot eliminate API/provider drift, rate limits or service changes. Concurrent evaluation can increase rate-limit pressure and correlated service failures; concurrency is fixed before the first session and the error/sensitivity rules remain fixed. Live sampling parameters remain the production defaults. Source/dependency hashes make method changes visible; they cannot freeze a remotely served model implementation.
- The dry-run provider scripts partial/correct code based on real injected advice and uses real query, tools, verification, episodes, distillation and accounting. It suppresses auto-memory forks through the mock child's fork-depth setting because no fork provider exists. It proves plumbing and discriminating checks, not model behavior; **every dry-run verdict is inconclusive**. Unit statistics tests separately establish that a planted arm effect can be detected.

Round 6 (`7b90238`, six sessions per family, concurrency 10) had an informative primary endpoint in every family: pooled 12/28 valid failures (42.9%).
